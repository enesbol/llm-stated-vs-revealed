# llm-stated-vs-revealed

Does an LLM's *stated* action match what it produces once forced to commit to
a concrete *artifact*? A registered replication and extension of one finding
from *Model Forensics* ([arXiv 2606.26071](https://arxiv.org/abs/2606.26071)):
the paper's own agentic-vs-third-person disclosure gap (65% vs 78%) is never
isolated from a confound, third-person framing asks "what would you do?"
(a **stated** action) while the agentic setting forces a real, sent artifact.
This repo holds the confound constant across environments and asks the
narrower question directly.

## Arms

Full definitions and the per-environment rationale: [`docs/arms.md`](docs/arms.md).

| Arm | Name | What it asks |
|---|---|---|
| S (called `A` in some configs, see `docs/arms.md`) | Stated action | "What would you do?", free prose, no artifact. |
| A (called `B` in some configs) | Artifact production | "Write the exact [email / submit payload] you would send." |
| T | Tool call | The model emits a structured action-schema in its own final response (only applicable where the environment's own released system prompt already wires in tool syntax, not built for any environment in this repo yet). |

Calling the Artifact arm "revealed behavior" overstates it, it is still a
stated artifact, never an executed one. `T`/executed-action (`X`) work is
tracked in [`docs/next.md`](docs/next.md), not built here.

## Findings

**Funding Email.** Primary result: **96.7% (Stated) vs. 90.0% (Artifact),
one-sided p=0.150, not significant** at n=30/arm — an honest, preregistered
null. Two findings alongside it (full detail: `docs/findings.md`): (1) the
published third-person rate did not reproduce (fresh 96.7% vs. the paper's
own historical 77.5%, same byte-locked prompt and provider pin, Fisher's
exact p≈0.013, a real positive finding, traced to refusal-rate drift
16.5%→3.3% and confirmed against a full census of the paper's 33 refused
completions, not a sample); (2) a reasoning-blind judge scored the arms in
the opposite order from the eventual human labels, because cut-off
completions state their real decision in `response_reasoning`, never in
visible content. A locked n=150/arm expansion ran after the original
`moonshotai` provider pin 404'd (confirmed live, $0 spent) and was
re-verified onto a working route (DeepInfra); generation and secondary
judge grading are complete, the prereg's primary human labeling of the
audit subset is not.

**Eval Tampering.** Pilot (n=30/arm) complete and fully human-labeled on
both arms. A locked n=150/arm expansion has also run: the Artifact arm is
complete via the same deterministic rule; the Stated arm has a 4-model-rater
consultative reading only, not yet the prereg's primary human pass (see
`docs/handoff/eval_tampering_v1_resolved.md`).

## Repository layout

```
docs/            overview, arm definitions, dated findings log, labeling rubric, next steps
src/stated_vs_revealed/
  run.py           one runner for any registered env (--dry-run supported)
  judge.py         generic LLM-judge harness (per-env rubric injected)
  stats.py         wilson_ci, two-proportion z-test, kappa
  analyze.py       per-env label merge + the pre-registered primary statistic
  labeling_sheet.py  builds an HTML labeling tool from any env's manifest
  prereg.py        hash-lock / verify a preregistration file
  envs/            one module per environment, registered in envs/__init__.py
envs/            DATA per environment: vendored source material, locked preregs, configs, rubric
results/live/    raw run outputs, one directory per environment per run, never overwritten
scripts/reproduce.sh   thin wrapper around `python -m stated_vs_revealed.reproduce`
tests/
```

## Adding a new environment

Five files, one registry line. See [`docs/arms.md`](docs/arms.md) and the
`Env` protocol in `src/stated_vs_revealed/envs/base.py`:

1. `envs/<name>/vendor/` + a README documenting exact source/revision/sha256.
2. `envs/<name>/rubric.md`: the label set and traps.
3. `src/stated_vs_revealed/envs/<name>.py` implementing `Env`.
4. `envs/<name>/prereg/*.json`, locked with `python -m stated_vs_revealed.prereg`.
5. `tests/envs/test_<name>_prompt_diff.py`: byte-identity except the terminal line.

Then one line in `src/stated_vs_revealed/envs/__init__.py`'s `ENVS` dict.
`run.py`, `stats.py`, `analyze.py`, `judge.py`, `labeling_sheet.py` are
shared and untouched by a new environment.

## Reproducing the numbers

```bash
pip install -e .
python -m stated_vs_revealed.reproduce
git diff --exit-code results/summary.json   # should be empty on a clean checkout
```

## Provenance

`vendor/`-equivalent material lives under each `envs/<name>/vendor/`,
byte-identical to its upstream source. See `PROVENANCE.md` and each
directory's own README. Never edited; if a vendored file looks wrong,
document the disagreement, don't "fix" it in place.

## Cost and safety discipline

Every live call sets `extra_body={"usage": {"include": True}}` and reads
`response.usage.cost` directly from OpenRouter, never a local token-count
estimate. No inference seed is ever sent. Every preregistration is hash-
locked before any API call and verified at runtime. Full list of enforced
invariants: `docs/findings.md`.
